# 0.32.3 — 禁言通知里「被禁言的人」和「管理员」认反了

群里的禁言排行榜（acumen 的 stats）上线后发现：榜上列的是动手的管理员，不是被禁言的人。
真机上一条 10 分钟的禁言，事件里 `user` 是管理员、`operator` 是被禁言的成员，两个人对调了。

- **原因**：`banFromXml` 假定灰条里先出现的账号是管理员。QQ 的句式其实是「成员 被管理员 管理员 禁言 10分钟」，
  **被禁言的人在前**。此前看起来对，是因为自己（群主）发起的禁言恰好撞上了 `Convert` 里一段「成员是自己就对调」的补丁。
- **现在**：`Notices.banPeople` 按两个账号之间的文字认人——有「被」就是成员在前，有「将」「把」或「了」就是管理员在前，
  都没有按成员在前（真机实测的顺序）。`Convert` 里那段对调补丁删掉了：自己被别人禁言时，自己就是 `user`，不再被误换。
  灰条里只有一个人时，`user` 是那个人、不带 `operator`，跟以前一样。
- **诊断**：`internal/status` 的 `inbound.last_ban_tip` 保留最近一条禁言灰条（去掉账号与昵称），
  `unread_ban_tip` 仍只放读不出时长的那条。想核对 QQ 实际的句式，看这两个字段就够了。

验证：33 项 JVM 测试通过，`NoticesTest` 新增「被」「将」「解除了」「被群主」「只有一个人」「没有账号」六种情形与解除灰条的人物顺序。
改动在 Java 层，代码内嵌在 Zygisk 的 `.so` 里：装机要覆盖模块文件后**重启手机**才生效。
