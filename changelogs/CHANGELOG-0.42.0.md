# 0.42.0 — 能力目录与幂等调用信封

这一版把「本实现端到底能做什么」从文档搬进协议，并给写动作补上一层重发保护。客户端由此可以把整张能力表交给模型，而不是等每一条 QQ 操作都被手写进一次工具 Schema。

- **能力目录**：`internal/capabilities` 新增 `catalog`，一条能力一行——名字、`kind`（`read` / `write` / `manage`）、参数说明、`mutating`、别名与一句用途。标准方法、核心内部动作与 `ExtraSvc` 注册的内核扩展全在同一张表里，由各自唯一的注册表生成，不手抄第二份。内核多接一个动作，客户端当天就能看见。
- **幂等调用信封**：`POST /v1/internal/call`，body 是 `{action, params, key?}`。同一把钥匙只真正执行一次：重发拿回第一次那份回执，带 `"replayed": true`。回执丢在半路（超时、连接被掐、客户端重启）时，客户端可以放心重发，上传文件、发公告这类动作不会做两遍。限流与内核离线不记账——那两类重发就该真的再试。
- **错误分得更清**：动作名从来不存在回 `404 code=unknown_action`；移除过的动作仍是 `404 code=removed_action`（带版本与原因）。两者在客户端都标成不可用，但运维要看的是完全不同的两件事。
- 新增 `CapabilitiesTest` 与 `CallLedgerTest`：目录必须覆盖每一个 `ExtraSvc` 动作、每条记录都能被分发层认下、分类与 `mutating` 自洽；信封则验钥匙重用、失败回放、暂时性失败不记、容量淘汰。

与 acumen 1.37.0 配套：智能体的 `satori_action` 多了一支 `capability`，名字与参数照这份目录抄，读动作不占额度，写动作占一次并沿用「群聊没往前走」的时效检查，管理类还要求本群开放管理。
