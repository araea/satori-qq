# 知弦 0.49.1：发出去的 @ 是真 @

## `atNtUid` 一直是空的

发消息时 `<at id="123456"/>` 一直带着 `atType=2` 与 `atUid`，但 `atNtUid`（QQ 的 uid）只从消息缓存里取。缓存里只记着在本进程里发过言的人，于是：

- 新入群的成员还没说过话，缓存里没有他的 uid，欢迎里的 @ 落下去是一段普通文字：客户端里点不开，对方也收不到提醒
- 消息发出去以后，这一段就定型了，不会再被追认成真 @

## 改法

- 缺 uid 时按「成员表缓存 → 资料服务」补齐，两步都是本地调用，不联网、不增加往返；补到就记进缓存，同一个人后续的 @ 直接命中
- 灰条里的成员变动（入群、退群、禁言、踢人）本来就带着当事人的 uid，转事件时顺手把 uin ↔ uid 记下来。入群欢迎紧接着发出的 @ 因此不必再查一次
- @ 后面的文字取成员的群名片或昵称（元素里带了 `name` 就用它），取不到才退回号码
- `dumpSent` 的诊断行带上 `atType` / `atUid` / `atNtUid`，能直接看出这一段是不是真 @

配合 0.48.2 的入群事件补全，客户端收到 `guild-member-added` 就能立刻发出真 @，不必先等 `guild.member.get`。
