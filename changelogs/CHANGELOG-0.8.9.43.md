## 0.8.9.43

0.8.9.42 的语音转写补上等待：那次发布里已经改对了「读哪个对象」，但漏了「听写是异步的」这一层，所以**第一次**读某条语音仍会拿到空字符串。

### 修的是什么

`translatePtt2Text` 用 `IOperateCallback`，只有码与一句短语——转写文字不走回调，而是稍后写回语音元素自己（`PttElement.text`）。0.8.9.42 在交完任务之后只重新取了一次记录，取回来时听写往往还没落盘，于是返回空串；再问一次就有了，看起来像随机失败。

现在交完任务会盯着元素看最多 3 秒（10 × 300ms）再返回，第一次调用就能拿到文字。

### 验证

测试群 46360522 的 8 条真实语音，从冷启动开始逐条读：

```
ok  15011ms "你在干什么？"
ok    114ms "你脸红了，来，让我看看。"
ok    238ms "我要向安娜酱学习，做一个单纯、善良、可爱的，男生。"
ok    171ms "我要像安娜这样，学习做一个单纯、可爱、善良的男生。"
ok    193ms "孙笑，你好大胆，在说什么？"
ok    169ms "怎么了？"
ok    195ms "有人可以加我微信吗？这才是最重要的。"
ok    130ms "这个群到了下午就没人了吗？"
```

第一条 15 秒是冷启动听写（换一条没听写过的语音也是这个量级），之后读同一条 100–240 毫秒。JVM 单测 19 项通过。

### 与前两版的关系

- 0.8.9.38 起这个动作一直只回状态码：读的是 `MsgElement` 外壳而不是它里面的 `PttElement`，`duration` 恒 0、「这段语音转不了」的判据全是假的
- 0.8.9.42 改对了读法（外壳给内核、内芯读字段），但没等异步听写
- 0.8.9.43 补上等待。听写没跑起来的语音仍会返回 `text` 为空，同时带上 `translate_status` / `duration` / `can_convert`，便于区分「内核还没转」和「这段本来就转不了」

版本号 0.8.9.43（versionCode 78），沿用同一签名密钥，支持从 0.8.9.42 直接覆盖升级。
