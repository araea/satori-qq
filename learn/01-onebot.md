01 · 合同
=========

## OneBot 11

**为什么。** 机器人框架不该认识 QQ 的类名。OneBot 是一份与实现无关的合同：动作名、事件名、消息段。ayjx 只认合同，不认 `IKernelMsgService`。

**怎么用到。** `OneBotHub` 把 JSON 动作派到 QQ 桥上，把 QQ 的 `MsgRecord` 译回事件。合同正文在 `docs/ONEBOT11_SUPPORT.md`。ayjx 实际会调的那一小撮已经冻住——多出来的动作是完整度，不是作业。

**去学。** 先当客户端用户：发 `send_msg`、看一条 `message` 事件。再读 OneBot 11 标准里「正向 / 反向」和「动作 / 事件」两节即可。不要从实现端入门。

## 正向 WebSocket

**为什么。** 反向是机器人开端口、实现端去连；正向相反。本模块住在 QQ 进程里，进程说没就没，适合自己当服务器、让 ayjx 来连。只绑 `127.0.0.1`：这是给本机机器人的插座，不是给公网的。

**怎么用到。** `net/WsServer.java` 手写 RFC6455。Bearer token 在握手时核对。`echo` 字段用来把响应对回请求。生命周期和心跳告诉机器人：现在到底在不在线。

**去学。** 握手、帧、掩码、关闭码。不必从零发明；读完规范再对照 `WsServer` / `WsConn`。鉴权想清楚一件事：空 token 等于不锁门；ayjx 空 token 则是不敲门。

## JSON 与消息段

**为什么。** 合同用 JSON。QQ 用 `MsgElement`。中间必须有人翻译。图、语音、合并转发在两边的形状完全不同。

**怎么用到。** `Convert.java` 是词典。`send_msg` 里若整段是 `node`，合同仍叫发消息，实现却要改走合并转发——这是 ayjx 的用法，不是标准里最显眼的那条路。

**去学。** 把「段」当成积木：`text` / `at` / `image` / `node`。先能在脑海里画出一条群消息拆成哪些段，再去看转换代码。
