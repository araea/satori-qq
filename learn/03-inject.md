03 · 注入
=========

## root

**为什么。** 没有最高权限，就没有 Zygisk，也就没有把模块塞进 QQ 的那条官方允许的缝（对系统而言是框架，对 QQ 而言是闯入）。这不是「方便调日志」，这是前提。

**怎么用到。** KernelSU 或 Magisk 一类。QQ **不能**进 denylist：要注入，就不能对 QQ 假装没 root。

**去学。** 只需要理解：root、模块目录 `/data/adb/`、开机脚本 `service.d`。不要从「获取 root」教程起家——那是另一门课，而且很容易学歪。

## Zygisk

**为什么。** Xposed 现在多半骑在 Zygisk 上：在 `Zygote` 孵化 App 时把框架 so 带进进程。QQ 的 Java 还没跑，钩子的座位已经在了。

**怎么用到。** 本机是 Zygisk Next。匿名内存模式用来去掉 maps 里的框架路径。没有这一层，后面的 maps 过滤都在补一个本可以不出现的指纹。

**去学。** Zygote 是什么、App 进程从哪来。不必写 Zygisk 模块；会看「某 so 出现在 `/proc/pid/maps`」就够进入下一篇。

## Xposed / vector

**为什么。** 要改的是 QQ 的 Java 方法（探测 hook 的、取会话的、发消息的）。Xposed 提供「在方法前后插入自己的代码」。vector 是本仓库用的、兼容 LSPosed API 的那一家。

**怎么用到。** 模块是一个带 Xposed 元数据的 APK。`Main implements IXposedHookLoadPackage`。框架把 QQ 放进作用域后，QQ 冷启动时才会调用 `handleLoadPackage`。手改配置数据库不一定生效，要以框架自己的 cli 或 Manager 为准。

**去学。** 写一个只 hook `Log.d` 或某个玩具 App 的模块，装上，冷启动，logcat 里看到自己。会了这一点，这个仓库的入口对你就不再是魔法。LSPosed 模块开发文档足够，不必先读框架源码。

## 作用域与冷启动

**为什么。** 作用域 = 对谁注入。冷启动 = 让新进程带上模块。漏掉任何一步，你都在调试一个根本没装上的幽灵。

**怎么用到。** 作用域里尽量只有本模块对着 QQ。能登录就不要卸。必须卸时先拿掉作用域，让 QQ 变回干净进程。

**去学。** 自己做一次：加作用域 → 冷启动 → 看见模块日志 → 再卸掉 → 日志消失。把这套肌肉记忆练出来，再碰 QQ。
