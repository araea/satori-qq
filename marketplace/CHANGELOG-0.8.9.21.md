## 0.8.9.21

- 新增常驻状态通知：Satori 服务运行时，在 QQ 通知栏常驻一条静默（`IMPORTANCE_LOW`）通知，随内核状态实时切换「运行中 / 等待登录 / 服务异常」，并显示账号、本地端口、事件连接数与在线时长，作为「机器人是否还活着」的直观指示。以 QQ 自身 Context 与通知权限发出，模块不声明任何权限；它不是前台服务、不提供保活权重。可用配置 `status_notification: false` 关闭。因随 QQ 身份发出，需 QQ 具备通知权限（Android 13+ 的 POST_NOTIFICATIONS，看门狗 protect_qq 会自动 pm grant）。
- 新增 `GET /healthz`（本地免鉴权）健康探针：直接返回 `online`/`listening`/`self_id`/在线时长，把「真在线」与「端口在听但内核离线」分开——补齐既有「端口在听却隐性离线」盲区，供看门狗与运维机器可读地判定，与通知栏状态同源。
- 常驻 / 防杀 / 网络保持机制分层评估并写入 `docs/ARCHITECTURE.md`：进程级防杀的重活由外部 root 看门狗承担（这是唯一能对抗国产 ROM 内核冻结的层级），进程内只做 HTTP 自愈与状态上报；刻意不新增易被检测、又打不过内核冻结的进程内保活，也不改 `oom_score_adj`。
- 在 QQ 9.3.60 真机复核：HTTP、登录态、发送与事件接收正常，通知栏常驻通知随重启/登录态正确刷新；反检测栈、签名、maps 隐藏与封包上报路径均未改动。
